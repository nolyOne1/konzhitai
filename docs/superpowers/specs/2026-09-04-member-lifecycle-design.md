# 云令团队成员生命周期设计

## 1. 背景

云令现有“团队与权限”模块已经支持查看成员和调整角色，登录模块支持成员自行修改密码，但管理员还不能创建、停用、移除或恢复成员，也不能为忘记密码的成员重置密码。本阶段补齐团队成员的完整生命周期，并保持全中文控制台体验。

## 2. 已确认决策

- 首版不接入邮件服务，也不发送邮件邀请。
- 管理员直接创建成员，并由系统生成一次性临时密码。
- 使用临时密码登录的成员必须先修改密码，完成后才能进入控制台。
- “删除成员”采用软删除：账号从默认列表移除，但历史任务、日志和审计记录继续保留成员身份。
- 管理员可以查看已移除成员并恢复账号。
- 管理员重置密码时生成新的一次性临时密码，并立即撤销该成员的现有会话。
- 不能停用、移除或降权当前登录管理员本人，也不能让系统失去最后一名有效管理员。

## 3. 目标

- 管理员能创建成员并分配一个或多个现有角色。
- 管理员能启用、停用、软删除和恢复成员。
- 管理员能重置其他成员密码。
- 一次性临时密码只在创建或重置成功后显示一次。
- 停用、移除和重置密码后，目标成员已有会话立即失效。
- 所有成员管理写操作进入现有审计日志。
- 现有成员和现有登录流程在迁移后保持可用。

## 4. 非目标

- 不接入邮件、短信、企业微信或飞书邀请。
- 不提供公开注册入口。
- 不实现邀请链接、单点登录或外部身份提供商。
- 不物理删除用户、历史执行记录或审计记录。
- 不重构现有角色模型，也不增加自定义角色编辑器。

## 5. 数据模型

在现有 `users` 表上增加：

- `must_change_password boolean not null default false`：是否必须先修改密码；
- `removed_at timestamptz null`：软删除时间，空值表示仍属于团队。

继续使用现有 `enabled` 字段表示账号是否允许登录。两者语义不同：停用账号仍显示在默认成员列表中，可以直接重新启用；移除账号默认隐藏，只在“已移除”筛选中显示并允许恢复。

迁移时现有用户的 `must_change_password` 为 `false`、`removed_at` 为空，不改变当前登录和改密体验。历史数据继续通过用户 ID 关联，不执行级联删除。

## 6. 服务与事务规则

扩展现有团队服务和仓储接口，提供创建、启停、移除、恢复、角色调整和管理员密码重置操作。涉及用户状态、角色、会话和审计的同一次管理操作必须在一个数据库事务中提交。

### 6.1 创建成员

管理员提交显示名称、邮箱和至少一个角色。服务规范化邮箱、校验角色、生成随机临时密码并保存密码哈希，同时把 `must_change_password` 设为 `true`。成功响应只返回一次临时密码；数据库、应用日志和审计详情均不得保存明文密码。

邮箱在所有未移除和已移除账号中保持唯一，避免恢复时发生身份冲突。创建重复邮箱返回明确中文错误，管理员可选择恢复原账号。

### 6.2 启用与停用

停用把 `enabled` 设为 `false` 并撤销目标成员全部会话。启用只把 `enabled` 恢复为 `true`；如果账号仍带有首次改密标记，登录后继续进入改密页。

### 6.3 移除与恢复

移除写入 `removed_at`、把 `enabled` 设为 `false` 并撤销目标成员全部会话。恢复清空 `removed_at`，账号保持停用状态，由管理员显式启用后才可登录，避免恢复操作意外开放访问。

### 6.4 调整角色

沿用现有多角色模型和角色校验。调整当前管理员本人或导致系统没有有效管理员的请求必须被拒绝。有效管理员指未移除、已启用并拥有 `admin` 角色的成员。

### 6.5 管理员重置密码

系统生成新的随机临时密码，更新密码哈希，将 `must_change_password` 设为 `true`，并撤销目标成员全部会话。成功响应只显示一次临时密码。管理员不能重置自己的密码，自己的密码继续通过现有个人改密入口修改。

## 7. HTTP API

沿用 `/api/members` 资源和现有权限中间件：

- `GET /api/members?status=active|disabled|removed|all`：读取成员列表；
- `POST /api/members`：创建成员，返回成员和一次性临时密码；
- `PUT /api/members/{id}/roles`：调整角色；
- `POST /api/members/{id}/disable`：停用成员；
- `POST /api/members/{id}/enable`：启用成员；
- `DELETE /api/members/{id}`：软删除成员；
- `POST /api/members/{id}/restore`：恢复成员；
- `POST /api/members/{id}/password/reset`：生成一次性临时密码。

列表读取沿用现有只读权限；所有写操作要求管理员权限。接口统一返回中文错误，包括字段无效、邮箱重复、成员不存在、状态冲突、禁止操作本人和最后管理员保护。

登录与会话接口返回 `must_change_password` 状态。带有该状态的会话只能访问当前会话、退出登录和修改密码接口；个人改密成功后在同一事务中清除该标记。前端据此强制进入改密页面。

## 8. 审计

新增或明确以下审计动作：

- `member.create`
- `member.enable`
- `member.disable`
- `member.remove`
- `member.restore`
- `member.roles.update`
- `member.password.reset`

审计记录操作者、目标成员、时间和不敏感的状态或角色变化。临时密码、密码哈希、会话令牌和完整请求体不进入审计详情。

## 9. 控制台交互

“团队与权限”页保留现有角色说明和成员表，在页头增加“创建成员”主按钮。成员表增加“全部、已启用、已停用、已移除”状态筛选，默认显示未移除成员。

管理员可从每行操作入口执行：调整角色、启用或停用、重置密码、移除或恢复。普通只读成员只看数据，不显示写操作。停用、移除和重置密码使用中文确认对话框，明确说明会话失效影响。

创建表单包含显示名称、邮箱和角色。创建或重置成功后打开“一次性临时密码”对话框，提供复制按钮，并提示关闭后无法再次查看。表单校验失败时保留已输入内容；操作成功后局部刷新成员数据，不整页跳转。

使用临时密码登录时，应用在进入其他路由前跳转到现有改密页面。页面说明这是首次登录或管理员重置后的必要步骤；改密完成后进入运行总览。

界面沿用现有控制台视觉体系、对话框焦点管理、键盘关闭和移动端响应式表格行为，所有新增文案使用中文。

## 10. 错误与并发处理

- 创建重复邮箱返回冲突，不覆盖原账号。
- 对已处于目标状态的启停、移除或恢复请求返回可理解的状态冲突。
- 角色变更、停用和移除在事务中锁定目标成员，并重新计算有效管理员数量，防止并发请求绕过最后管理员规则。
- 撤销会话与成员状态修改必须共同成功或共同回滚。
- 临时密码响应在网络失败后不可重新查询；管理员需要重新执行密码重置生成新密码。

## 11. 测试设计

### 11.1 后端

- 创建成员时规范化邮箱、保存哈希、分配角色并设置首次改密标记。
- 拒绝重复邮箱、空角色和未知角色。
- 启停、移除、恢复按定义更新状态并撤销会话。
- 重置密码生成新哈希、撤销会话并设置首次改密标记。
- 禁止操作本人和破坏最后一名有效管理员。
- 并发管理员状态变更仍保留至少一名有效管理员。
- 所有成功写操作产生正确审计，且不包含临时密码。
- 强制改密会话只能调用允许的接口；完成改密后恢复正常访问。
- 数据库迁移对现有账号保持兼容。

### 11.2 前端

- 管理员看到创建和行操作，非管理员不显示写操作。
- 创建表单校验、提交、错误保留和成功刷新。
- 状态筛选正确显示启用、停用和已移除成员。
- 启停、移除、恢复、角色调整和重置密码流程正确。
- 一次性临时密码支持复制，关闭后不在界面状态中保留。
- 临时密码登录后强制进入改密页，完成后进入控制台。
- 对话框支持 Escape、焦点循环与焦点归还。

### 11.3 验收

- 运行后端单元与数据库集成测试。
- 运行前端测试和生产构建。
- 运行覆盖创建成员至首次改密登录的端到端流程。
- 通过 CI 后再生成部署候选；本阶段不自动修改线上环境。

## 12. 实施边界

实现顺序为数据库迁移与仓储、团队服务、HTTP API、登录强制改密、前端成员管理、端到端测试和中文文档。以功能完整为优先，不扩展邮件邀请、SSO、自定义角色或其他安全平台能力，但保留会话失效、最后管理员保护和临时密码不落日志这些维持系统可用性的必要规则。
