# 云令脚本调度平台设计方案

日期：2026-08-28  
状态：已完成交互确认，等待最终文档审阅

## 1. 项目目标

从零建设一个全中文、多服务器的脚本管理与任务调度平台，管理系统部署在腾讯云，首台执行节点位于京东云，后续可以继续接入其他云厂商或自建服务器。

平台需要统一管理脚本、版本、运行参数和定时计划，根据各服务器的在线状态、剩余资源、当前任务和运行环境自动选择执行节点。没有可分配服务器时，任务进入持久化等待队列，在资源释放、服务器恢复或新服务器加入后自动重新调度。

## 2. 首期范围

### 2.1 核心能力

- 全中文运行控制台，集中展示服务器负载、运行任务、排队数量、成功率、脚本同步和最近动态。
- 多服务器注册、分组、标签、启用、停用、排空和健康状态管理。
- 脚本创建、编辑、导入、发布、版本比较、同步、回滚和漂移检测。
- 普通参数、敏感参数、运行环境、资源需求、超时、并发和重试策略配置。
- 手动执行、Cron 定时执行、任务启停、人工终止和重新执行。
- 基于服务器状态和资源的自动分配，无合适节点时自动排队。
- 实时状态与日志查看、历史记录检索和日志下载。
- 管理员、运维人员、脚本开发者、只读成员四类角色与完整审计日志。
- 后续服务器通过安装轻量代理接入，不依赖云厂商专有接口。

### 2.2 首期不包含

- 可视化 DAG 工作流、跨任务条件分支和人工审批流。
- Kubernetes 集群调度或容器编排平台替代能力。
- 多地域控制中心主动—主动高可用。
- 计费、配额售卖或面向外部租户的 SaaS 多租户体系。

这些能力不进入首期界面与数据模型，避免首版范围失控；核心接口会保留扩展边界。

## 3. 产品信息架构

### 3.1 运行总览

- 在线服务器、正在执行、排队任务和今日成功率四项核心指标。
- 服务器负载列表，展示 CPU、内存、运行任务数、在线状态和代理版本。
- 实时任务列表，展示任务状态、执行服务器和调度依据。
- 排队仅作为任务状态和调度规则存在，不设置独立的排队管理页面。
- 脚本同步摘要和最近系统动态。

### 3.2 脚本中心

- 脚本列表、分类、标签、运行环境和当前发布版本。
- 浏览器编辑器、文件导入、参数定义、资源要求和版本说明。
- 发布目标选择：全部兼容服务器、指定服务器组、指定标签或按需分发。
- 版本比较、同步进度、漂移状态和一键回滚。

### 3.3 任务调度

- 任务定义、绑定脚本版本策略、参数、资源需求和目标服务器约束。
- 手动触发与 Cron 定时规则。
- 优先级、最大并发、超时、最大等待时间和失败重试策略。
- 任务定义可启用或停用；停用后不再生成新的执行实例。

### 3.4 执行记录

- 按任务、脚本、服务器、状态和时间筛选执行实例。
- 实时日志、结构化运行信息、资源使用、退出码和失败原因。
- 终止、重新执行、下载日志和关联审计记录。

### 3.5 资源与系统

- 服务器、服务器组、标签、能力、资源与心跳状态。
- 参数与密钥，敏感值默认不可回显。
- 团队成员、角色权限、登录与审计。
- 系统级调度、日志保留、告警和安全设置。

## 4. 总体架构

平台采用“腾讯云中央控制中心 + 各执行服务器轻量代理”的结构。代理始终主动连接中央服务，中央服务不需要日常主动登录执行服务器。

### 4.1 中央控制中心

- React + TypeScript：全中文 Web 控制台。
- Go API 服务：用户接口、权限、脚本版本、任务配置、服务器管理和实时事件。
- Go 调度服务：排队、候选节点筛选、评分、资源租约和任务分配。
- PostgreSQL：持久化业务数据和审计数据。
- Redis：任务等待队列、调度事件、资源租约和短期状态。
- S3 兼容对象存储：脚本包、运行产物和较大历史日志。首期使用 MinIO，接口允许后续切换腾讯云 COS。
- Docker Compose：在腾讯云上部署控制台、API、调度器、PostgreSQL、Redis 和 MinIO。

### 4.2 执行代理

- Go 单文件程序，以 systemd 服务运行。
- 主动建立 TLS 加密连接，上报心跳、能力、资源、任务状态和日志。
- 下载并校验中央脚本版本，在独立工作目录内执行。
- 支持可配置运行环境，包括 Shell、Python、Node.js 和 PowerShell；实际可用能力由各服务器代理探测并上报。
- 网络中断时本地缓冲日志和状态，恢复后按序号续传。

### 4.3 通信方式

- 代理注册、脚本下载和管理接口使用 HTTPS。
- 代理使用经过认证的 WebSocket 长连接接收任务并上报心跳、状态和日志；断线后指数退避重连。
- Web 控制台使用 SSE 接收任务状态和日志更新。
- 每次下发包含唯一执行令牌、脚本版本、参数、资源约束和超时时间。

## 5. 脚本版本与同步

### 5.1 唯一可信来源

中央脚本中心是纳管脚本的唯一可信来源。首次接入可由代理扫描允许目录并导入脚本；导入完成后，服务器纳管目录不再作为编辑入口。

### 5.2 版本规则

- 编辑内容先保存为草稿。
- 发布生成不可变版本，记录修改人、发布时间、发布说明、内容校验值和运行环境。
- 任务可以锁定固定版本或跟随最新已发布版本。
- 每个执行实例在创建时解析出确定版本，之后不随新发布改变。
- 正在运行的任务继续使用启动时版本，新任务使用其已解析版本。

### 5.3 分发规则

- 发布后按目标规则同步到全部兼容服务器、服务器组或标签集合。
- 代理下载到临时位置，完成校验后原子切换当前版本。
- 同步失败不会破坏旧版本；服务器在缺少任务所需版本时不得接收该任务。
- 失败自动重试并显示原因，连续失败达到阈值后标记节点异常。
- 按需分发的脚本在任务分配后下载，调度评分优先选择已经缓存相同版本的服务器。

### 5.4 回滚与漂移

- 回滚通过重新发布历史内容形成新版本，保证版本历史只追加、不覆盖。
- 代理定期校验纳管文件；服务器侧修改会标记为“版本漂移”。
- 漂移节点暂停接收该脚本的新任务，告警后由中央版本重新同步。

## 6. 任务与调度模型

### 6.1 任务定义

任务定义包含：脚本与版本策略、普通参数、敏感参数引用、触发方式、优先级、目标标签、资源需求、最大并发、超时、最大等待时间、重试策略和幂等声明。

### 6.2 执行状态

执行实例使用以下状态：

- 排队中：已创建，等待调度。
- 调度中：正在评估候选服务器。
- 已分配：资源租约已创建，等待代理确认。
- 同步脚本：代理正在获取所需版本。
- 运行中：脚本进程已经启动。
- 成功：进程正常退出并满足成功条件。
- 失败：脚本退出失败或执行环境错误。
- 已超时：超过配置时间并被终止。
- 已取消：用户或系统明确取消。
- 已过期：排队时间超过任务配置的最大等待时间。
- 状态待确认：代理失联，中央无法确认进程最终状态。

任务定义的“已停用”不是执行实例状态；停用只阻止生成新的执行实例。

### 6.3 候选节点筛选

调度器只保留同时满足以下条件的服务器：

- 代理在线且未被停用或排空。
- 服务器标签满足任务约束。
- 具备脚本需要的运行环境。
- 当前运行数未达到服务器或任务并发上限。
- 预留后的 CPU、内存和磁盘仍满足任务需求。
- 服务器未因脚本漂移、同步失败或健康异常被隔离。

### 6.4 节点评分

候选节点根据剩余内存、剩余 CPU、当前任务数、脚本版本缓存、近期分配公平性和服务器权重综合评分。默认优先选择资源余量大、任务较少且已经缓存脚本版本的节点。界面显示主要分配依据，便于运维人员理解调度结果。

### 6.5 资源租约

- 分配前在 Redis 中原子创建资源租约，同时把分配结果持久化到 PostgreSQL。
- 租约包含任务执行令牌、服务器、CPU、内存、磁盘和过期时间。
- 代理确认启动后续租；任务完成、取消或明确失败后立即释放。
- 租约避免多个调度器或并发事件将同一份剩余资源重复分配。

### 6.6 无可分配服务器

- 没有合适节点时，执行实例保持“排队中”，不计为失败。
- 队列默认按优先级降序、进入队列时间升序排序。
- 任一任务释放资源、服务器恢复、服务器新增、标签或能力变化时立即触发重新调度。
- 每 15 秒执行一次兜底扫描，避免事件丢失导致任务长期卡住。
- 任务默认无限等待，直到满足条件、人工取消或达到单独配置的最大等待时间。停用任务定义只阻止生成新的执行实例，不影响已经排队的实例；界面另行提供“停用并取消等待任务”操作。

## 7. 完整数据流

1. 用户发布脚本，中央服务创建不可变版本并上传脚本包。
2. 手动或定时触发创建执行实例，解析确定脚本版本并进入等待队列。
3. 调度器读取任务和最新服务器快照，筛选、评分并尝试创建资源租约。
4. 没有候选节点时保留排队状态；有候选节点时写入分配结果并通知代理。
5. 代理确认任务、同步并校验脚本，在独立目录和资源限制下启动进程。
6. 代理持续回传日志、心跳、资源使用和状态；中央服务将实时事件推送给控制台。
7. 进程结束后写入退出码和最终状态，释放资源租约并唤醒等待队列。
8. 历史日志达到数据库阈值后归档至对象存储，记录仍可从执行详情访问。

## 8. 异常处理与可靠性

### 8.1 服务器与网络异常

- 心跳超时后节点立即停止接收新任务。
- 失联时正在运行的任务标记“状态待确认”，代理恢复后通过执行令牌对账。
- 尚未启动的任务可以安全重新入队；已经启动但状态未知的任务默认不跨节点自动重跑。
- 只有声明为幂等且允许自动重试的任务，才可在租约过期和确认原进程停止后自动重新分配。

### 8.2 脚本与执行异常

- 校验失败不执行，删除临时文件后重新下载。
- 每次执行使用独立工作目录和专用系统账号。
- 通过 systemd 临时单元或等价的 cgroup 能力限制 CPU、内存、进程数和运行时间。
- 终止任务时先发送正常终止信号，等待宽限期后终止整个进程组。
- 日志和产物设置大小上限，超限时保留明确错误原因。

### 8.3 中央服务异常

- PostgreSQL 是最终业务状态来源，中央服务重启后从持久化记录恢复未完成执行。
- Redis 数据丢失时可根据 PostgreSQL 中的排队和租约记录重建短期状态。
- 任务下发和状态上报使用执行令牌与单调递增序号去重。
- 日志按分块序号确认，代理只清理已确认的本地缓冲。

## 9. 安全与权限

- 不保存现有 root 密码；正式接入时创建专用代理账号和独立密钥。
- 代理凭据支持轮换和吊销，每台服务器使用独立身份。
- 控制中心与代理之间使用 TLS；敏感部署可启用双向 TLS。
- 敏感参数加密保存，不通过普通任务参数明文传递，界面和日志自动脱敏。
- 参数使用类型化定义传递给执行器，不把用户输入直接拼接为 shell 命令。
- 角色分为管理员、运维人员、脚本开发者和只读成员。
- 登录、发布、回滚、同步、执行、终止、密钥操作和权限变更全部写入审计日志。
- 纳管脚本目录和工作目录使用最小文件权限，代理不得访问未授权路径。

## 10. 核心数据实体

- 用户、角色、权限、用户角色关系。
- 服务器、服务器组、服务器标签、代理身份、能力与最新资源快照。
- 脚本、脚本草稿、脚本版本、脚本发布目标和服务器同步状态。
- 参数定义、密钥、运行环境和资源规格。
- 任务定义、定时计划、执行实例和重试关系。
- 资源租约、状态事件、日志分块和运行产物。
- 审计日志和系统告警。

实体之间使用稳定标识关联；脚本版本、执行实例、审计记录和日志索引只追加，不原地覆盖历史事实。

## 11. 测试策略

### 11.1 单元测试

- 候选节点筛选、评分、优先级和公平性。
- 资源租约的原子创建、续租、释放和过期。
- Cron 触发、并发限制、最大等待和重试判断。
- 参数校验、敏感值脱敏和权限判定。
- 状态机合法迁移与重复事件去重。

### 11.2 集成测试

- 使用多个模拟代理验证分配、资源竞争、排队和自动唤醒。
- 验证脚本发布、同步、校验失败、断点重试、漂移和回滚。
- 验证代理断线、恢复对账、日志续传和状态待确认处理。
- 验证 PostgreSQL、Redis 或中央服务重启后的状态恢复。

### 11.3 端到端测试

- 从登录、发布脚本、创建任务、手动执行到查看实时日志的完整流程。
- 定时触发后因资源不足排队，资源释放后自动分配并成功执行。
- 停用任务、取消排队、终止运行、回滚版本和权限限制。
- 中文界面、键盘操作、移动端布局和关键状态的可访问性。

### 11.4 故障演练

- 代理进程被终止、网络抖动、脚本包损坏、日志积压和磁盘空间不足。
- 同时释放多台服务器资源时验证无重复分配和无资源超卖。
- 未声明幂等的任务状态未知时验证系统不会自动重复执行。

## 12. 验收标准

- 可以新增至少两台执行服务器，并在同一控制台查看状态与资源。
- 同一脚本可以发布至多台服务器，更新后同步状态清晰可见，失败可重试，历史版本可回滚。
- 可以配置参数、资源需求、手动触发和 Cron 定时计划。
- 调度器不会把任务分配给离线、资源不足、运行环境不匹配或已达到并发上限的服务器。
- 没有合适服务器时任务保持排队，资源释放或服务器上线后自动运行。
- 执行状态和日志可实时查看，网络中断后可以续传。
- 脚本更新不影响已经运行的执行实例。
- 权限、敏感信息脱敏和关键操作审计按设计生效。
- 核心单元、集成和端到端测试全部通过后才能部署至生产环境。

## 13. 实施顺序

1. 建立仓库、开发环境、数据模型和全中文控制台框架。
2. 实现用户、权限、服务器、脚本和任务配置基础能力。
3. 实现代理注册、心跳、能力探测和资源采集。
4. 实现脚本版本、对象存储、同步、校验、漂移与回滚。
5. 实现队列、调度器、资源租约和自动唤醒。
6. 实现代理执行隔离、状态、日志、取消、超时和恢复对账。
7. 完成审计、安全加固、测试、Docker Compose 部署和首台服务器接入。

## 14. 已确认的关键决策

- 产品是服务器脚本管理与调度平台，不是人员任务看板。
- 中央控制中心部署在腾讯云，执行服务器可跨云扩展。
- 首期即使用轻量代理，SSH 只用于首次安装和紧急诊断。
- 脚本以中央仓库为唯一可信来源，并采用不可变版本。
- 自动调度考虑在线状态、运行任务、资源、能力、标签和脚本缓存。
- 无合适服务器时任务进入等待队列，队列是运行规则而非独立功能面板。
- 控制台沿用已确认的深绿色运维控制台方向并保持全中文。
