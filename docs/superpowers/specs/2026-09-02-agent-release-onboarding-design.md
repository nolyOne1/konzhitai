# 云令代理发布与一键接入设计

日期：2026-09-02  
状态：已确认，待书面复核

## 1. 背景与目标

云令已经具备一次性注册令牌和服务器接入向导，但新服务器仍需人工把 `/tmp/install.sh` 与 `/tmp/yunling-agent` 上传到目标主机。这会增加接入步骤，也容易因为上传了错误版本、错误架构或不完整文件而失败。

本阶段把现有向导升级为真正的一条命令接入：

- 云令构建并发布 Linux x86_64 与 Linux ARM64 两种代理安装包。
- 新服务器通过云令控制平面的 HTTPS 地址下载匹配架构的安装包。
- 下载后必须先校验精确 SHA-256，再以 root 权限安装。
- 注册令牌仍由管理员在控制台创建、只显示一次，并在目标服务器终端中隐藏输入。
- 接入过程不把令牌写进复制命令、URL、Shell 历史、进程参数或普通日志。
- 发布清单不可用时禁止签发注册令牌，避免产生无法使用的令牌。

本阶段不实现已接入代理的自动升级，不支持 Windows、macOS 或 Linux 以外的平台，也不自动安装操作系统依赖。

## 2. 已确认的产品决策

- 首期支持 `linux/amd64` 与 `linux/arm64`，兼容展示名称为 Linux x86_64 与 Linux ARM64。
- 安装命令根据 `uname -s` 和 `uname -m` 自动选择安装包；不支持的平台直接给出中文错误。
- 代理安装包公开下载，但使用版本与内容哈希组成不可变地址；安装包不包含注册令牌、服务器凭据或其他秘密。
- 每个安装包都在发布清单中提供 SHA-256，目标服务器必须校验一致后才能安装。
- 注册令牌只用于代理注册，不作为安装包下载凭据，因此不会出现在 `curl`、`wget` 参数或下载日志中。
- 安装程序只做环境检查，不自动执行 `apt`、`yum`、`dnf` 等包管理操作。
- 缺少依赖时停止安装，并用中文列出缺失项和修复方向。
- 向导必须先成功取得有效发布清单，之后才允许创建一次性令牌。
- 令牌有效期继续保持 10 分钟；下载或校验失败不会消费令牌，注册成功才消费令牌。
- 当前已接入的京东云节点继续运行原代理，本次上线不主动替换或重启它。

## 3. 总体架构

### 3.1 构建产物

`deploy/Dockerfile.services` 在服务镜像构建阶段分别执行：

- `GOOS=linux GOARCH=amd64 CGO_ENABLED=0`
- `GOOS=linux GOARCH=arm64 CGO_ENABLED=0`

代理版本由构建参数传入，并通过 Go 链接参数写入代理二进制；未显式传入时默认仍为 `0.1.0`。运行时的版本上报与发布清单必须来自同一个构建版本值，避免安装包名称与代理自报版本不一致。

每种架构生成一个独立 `.tar.gz`，内容固定为：

- `yunling-agent`
- `install.sh`
- `yunling-agent.service`
- `yunling-run@.service`
- `50-yunling-agent.rules`

构建过程为每个安装包计算 SHA-256 和字节数，并生成随 API 镜像发布的代理清单。API 镜像内的发布目录只读，不在运行时重新打包，也不从数据库或对象存储动态拼接文件。

### 3.2 发布服务

API 启动时加载内置发布清单，并逐项验证：

- 版本、操作系统和架构均为允许值。
- 文件名和文件路径与清单完全匹配。
- 安装包存在且为普通文件。
- 实际字节数与 SHA-256 和清单一致。
- 同一个操作系统与架构只有一个当前版本。

校验成功后才对外提供发布清单与安装包。若加载或校验失败，代理发布子系统进入“不可用”状态，清单接口返回 `503`，但登录、调度、脚本和现有代理接口继续服务。错误日志只包含版本、架构和安全的错误摘要，不输出路径外内容或任何凭据。

### 3.3 Web 接入向导

管理员打开“接入新服务器”向导时，Web 先请求代理发布清单。只有同时存在 `linux/amd64` 和 `linux/arm64` 的完整、有效记录时，才允许填写节点信息并创建一次性令牌。

令牌创建成功后，向导依据已经取得的清单生成一段可整体复制的 Bash 安装命令。命令包含两个架构安装包的不可变下载地址和 SHA-256，但不包含令牌值。目标服务器执行命令后，由已校验的安装程序在终端中隐藏读取一次性令牌并完成注册。

## 4. 公共发布接口

新增两个无需登录的只读接口，并继续复用 Caddy 现有 `/api/*` 转发，不新增公网端口。

### 4.1 当前发布清单

`GET /api/releases/agent/latest`

成功响应示例：

```json
{
  "version": "0.1.0",
  "artifacts": [
    {
      "os": "linux",
      "arch": "amd64",
      "file_name": "yunling-agent-0.1.0-linux-amd64.tar.gz",
      "byte_size": 12345678,
      "sha256": "64 位小写十六进制摘要",
      "download_url": "/api/releases/agent/0.1.0/摘要/yunling-agent-0.1.0-linux-amd64.tar.gz"
    }
  ]
}
```

清单只返回相对下载路径，由浏览器使用当前可信控制平面来源拼接，避免部署域名配置错误生成跨站下载命令。响应使用 `Content-Type: application/json`、`Cache-Control: no-cache, no-store, must-revalidate` 和 `X-Content-Type-Options: nosniff`。

### 4.2 不可变安装包

`GET /api/releases/agent/{version}/{sha256}/{fileName}`

服务端不把路径参数直接用于文件系统查找，而是用“版本 + SHA-256 + 文件名”在启动时已验证的发布清单中做精确匹配。未知版本、摘要、文件名或组合统一返回 `404`，禁止目录遍历和任意文件读取。

成功响应包含：

- `Content-Type: application/gzip`
- `Content-Disposition: attachment`，文件名来自可信清单
- `Content-Length`，与清单字节数一致
- `ETag`，值由 SHA-256 派生
- `Cache-Control: public, max-age=31536000, immutable`
- `X-Content-Type-Options: nosniff`

支持条件请求；命中 `If-None-Match` 时返回 `304`。安装包地址包含内容哈希，所以后续发布新版只能生成新地址，不能覆盖旧内容。

公开发布接口设置独立的合理读取超时、并发和速率边界，但不记录完整查询值或响应内容。公开下载不扩大注册权限，代理仍必须持有效一次性令牌才能创建服务器身份。

## 5. 一条命令安装流程

复制命令是一个可整体粘贴的 Bash 命令块，按以下顺序运行：

1. 启用严格错误处理，并建立 `mktemp -d` 临时目录和退出清理陷阱。
2. 检查操作系统是否为 Linux，并将 `x86_64` 映射为 `amd64`、`aarch64` 或 `arm64` 映射为 `arm64`。
3. 检查当前架构在复制命令内是否有对应的不可变 URL 与 SHA-256。
4. 检查下载阶段所需的 Bash、`curl` 或 `wget`、`tar` 与 `sha256sum`。
5. 只通过 HTTPS 从当前云令控制平面下载匹配的安装包，不把令牌用作下载参数。
6. 以严格的完整字符串比较校验安装包 SHA-256；不一致时立即删除临时文件并退出。
7. 在临时目录中解包，拒绝绝对路径、`..` 路径、符号链接、额外文件和缺少必需文件的归档。
8. 校验 `install.sh` 和代理二进制都是普通文件，再调用已校验的安装程序。
9. 当前用户不是 root 时使用 `sudo` 提权；没有 root 权限或 `sudo` 时给出中文错误。
10. 安装程序检查 systemd 版本至少为 240、polkit 规则目录和所需系统命令。
11. 安装程序在提权后的交互式终端隐藏读取一次性令牌，执行现有安全安装与注册流程。
12. 无论成功、中断或失败，都清空 Shell 变量并删除临时目录；注册完成后从代理环境文件中移除令牌和临时控制地址。

下载、解包和校验均在提权前完成，只有内容验证通过后才执行 root 安装。命令不使用 `curl | sh`，也不执行未经哈希验证的远程脚本。

如果终端不支持隐藏输入或标准输入不是交互式终端，安装程序停止并提示管理员在交互式 SSH/网页终端中重新运行，不允许回退到明文令牌参数。

## 6. 安装程序边界

现有 `deploy/agent/install.sh` 继续负责安全落盘和注册，但接口调整为：

- 控制平面地址可作为非秘密参数传入，且必须是 HTTPS 来源。
- 注册令牌只能由安装程序从交互式终端隐藏读取，不能接受命令行参数、环境变量或普通标准输入重定向。
- 所有错误处理和退出陷阱都必须保留原始失败退出码。
- 安装过程创建并复用现有 `yunling-agent`、`yunling-runner` 用户与组。
- 二进制、systemd 单元、polkit 规则和配置文件继续使用最小权限落盘。
- 临时 `agent.env` 权限为 root-only；代理换取长期凭据后移除一次性令牌并重启。
- 日志不得打印令牌、代理长期凭据、完整认证响应或包含秘密的环境变量。

预检只报告问题，不修改操作系统包。缺失依赖时错误必须包含：缺失项、最低要求以及“安装依赖后重新执行原命令”的中文说明。发行版具体安装命令可作为提示，但不自动执行。

安装脚本重复运行时不得破坏已存在的有效代理身份。首期采用保守策略：检测到已有代理凭据时停止，提示管理员先在控制台确认服务器身份，不自动覆盖或重新注册。

## 7. 注册令牌与失败语义

发布清单加载和令牌签发按以下状态机处理：

- `loading_release`：正在读取代理版本，表单可查看但不能签发令牌。
- `release_unavailable`：清单请求失败、格式错误或缺少任一支持架构；显示重试入口，不能签发令牌。
- `ready`：清单完整，可以创建令牌。
- `issuing`：正在创建服务器和令牌；禁止重复提交和关闭对话框。
- `issued`：只显示一次令牌、完整安装命令和 10 分钟有效期。

发布清单成功后到令牌签发前如果版本发生变化，本次向导仍使用已加载清单中的不可变地址；旧安装包不会被覆盖。刷新或重新打开向导会读取新版本。

失败处理如下：

- 不支持的操作系统或架构：安装未开始，令牌不消费。
- 缺少依赖、无 root 权限或非交互终端：安装未开始，令牌不消费。
- 下载失败、安装包不存在或网络中断：停止并清理，令牌不消费，可在 10 分钟内重试。
- SHA-256 不一致或归档内容异常：停止并清理，绝不执行安装包，令牌不消费。
- systemd 或 polkit 不满足要求：停止安装并清理临时秘密，令牌不消费。
- 注册请求到达控制平面但令牌无效、已使用或过期：显示可辨认但不泄露内部信息的中文错误，管理员需重新创建令牌。
- 注册成功：原子消费令牌，写入代理长期凭据，后续重复请求不得创建第二个身份。

一次性令牌继续复用现有服务端哈希保存、到期时间、单次消费、管理员权限和审计机制，本阶段不建立第二套令牌实现。

## 8. 控制台交互

服务器页继续保持现有中文控制台样式，接入向导调整为：

- 打开时显示“正在读取代理版本”。
- 清单可用后显示“代理版本 0.1.0”“支持 Linux x86_64 / ARM64”。
- 清单不可用时显示中文原因摘要和“重新加载”，不显示可提交的创建按钮。
- 创建成功页标题改为“一条命令安装并接入”。
- 删除手动上传 `/tmp/install.sh` 和 `/tmp/yunling-agent` 的说明。
- 明确提示令牌只显示一次、10 分钟内有效、注册成功后自动失效。
- 提供复制完整命令按钮，并保留复制成功、复制失败的可访问提示。
- 命令预览不得渲染或拼接令牌；令牌本身单独显示并可单独复制。
- 签发期间禁止关闭；签发完成后关闭前提示令牌不会再次显示。
- 保留键盘焦点圈、对话框焦点约束、Escape 边界和移动端安全区适配。

发布清单错误、权限错误、网络错误和令牌签发错误使用不同中文信息，但不向用户展示服务端堆栈、主机文件路径或内部响应正文。

## 9. 安全设计

- 安装包可以公开获取，因为只包含代理程序和安装资产，不包含任何环境秘密或服务器身份。
- TLS 提供传输保护，SHA-256 提供安装前内容完整性验证；二者缺一不可。
- 清单响应不可长期缓存，带哈希的安装包可永久缓存，防止内容与地址发生歧义。
- API 只提供启动时已验证的白名单文件，拒绝任意路径、范围外文件和运行时目录扫描。
- 归档提取前验证条目集合和路径，提取后再验证文件类型，避免路径穿越和符号链接替换。
- 下载和校验以普通用户执行，root 权限只用于最终安装。
- 令牌不进入复制命令、URL、命令参数、下载头、Shell 历史、进程列表或普通日志。
- 临时文件位于随机私有目录，退出陷阱覆盖正常结束、错误和常见终止信号。
- Web 不信任清单中的任意外部 URL，只接受同源 `/api/releases/agent/` 相对路径、允许的版本格式、架构和 64 位小写 SHA-256。
- 公开端点不返回源码、构建环境、内部文件路径或其他服务二进制。

## 10. 可观测性与审计

发布子系统至少暴露以下安全运行信息：

- 发布清单是否可用。
- 当前代理版本。
- 可用架构数量。
- 最近一次启动校验的成功时间或脱敏失败原因。
- 每个安装包的版本、架构、字节数与摘要前缀。

访问日志可记录响应状态、字节数、架构和版本，但不记录注册令牌。发布清单校验失败进入服务日志和现有内部告警路径；单次公网下载失败不生成高优先级业务告警，避免网络探测造成噪声。

令牌创建、服务器注册成功与失败继续沿用现有审计动作。审计信息只记录服务器、操作者、结果和安全错误码，不记录明文令牌或代理凭据。

## 11. 测试策略

### 11.1 Go 单元与接口测试

- 发布清单成功加载并稳定排序两个架构。
- 文件缺失、字节数不一致、SHA-256 不一致、重复架构和未知架构时子系统不可用。
- 清单接口返回预期字段、无缓存头和 `503` 失败状态。
- 安装包接口只接受清单中的精确组合，拒绝路径遍历、未知文件和错误摘要。
- 下载响应的内容、长度、ETag、不可变缓存头、`304` 和 `nosniff` 正确。
- 公开发布接口不要求会话，但不会绕过其他 `/api` 路由的认证。
- 代理构建版本和运行时版本上报一致。

### 11.2 Web 测试

- 打开向导先加载发布清单，加载期间不能签发令牌。
- 清单失败、字段非法、跨源 URL 或缺少一种架构时禁止签发并可重试。
- 清单成功后显示版本和两种支持架构。
- 生成命令包含两个正确的不可变地址与 SHA-256，并根据目标架构选择。
- 命令和命令预览中不存在一次性令牌。
- 成功页不再出现手动上传 `/tmp` 文件的旧提示。
- 复制成功、复制失败、权限失败、重复提交、关闭保护和焦点行为保持正确。

### 11.3 Shell 与构建验证

- 对生成的 Bash 命令和 `install.sh` 执行语法检查。
- 模拟缺少工具、未知架构、下载失败、哈希错误、归档异常、非交互终端、无 sudo 和安装失败，确认返回非零退出码。
- 验证所有失败分支保留原始失败状态并删除临时目录，不在输出和进程参数中出现测试令牌。
- Docker 构建后实际解包两个安装包，确认固定文件集合、权限、无符号链接和无额外文件。
- 使用 `file` 或 ELF 头检查二进制分别为 Linux amd64 与 Linux arm64。
- 对下载文件重新计算 SHA-256，确认与清单和 URL 一致。

### 11.4 集成与生产验收

上线前在隔离容器或临时 Linux 主机验证两个架构分支的下载、校验和预检。没有备用真实服务器时不创建生产测试令牌，也不在现有京东云节点上覆盖安装。

生产上线按以下顺序验收：

1. 重建 API 与 Web 镜像并滚动替换对应容器。
2. 验证 API、Web、Scheduler、Ops、数据库和对象存储健康，现有京东云代理自动保持或恢复连接。
3. 访问发布清单，确认版本、两个架构、相对地址、字节数和 SHA-256 完整。
4. 分别公网下载两个不可变安装包，重新计算 SHA-256 并核对内容清单与 ELF 架构。
5. 验证控制台向导显示代理版本和“一条命令安装并接入”，不再要求手动上传文件。
6. 验证未登录用户只能下载公开发布文件，不能创建注册令牌或访问管理接口。
7. 后续第一次新增真实服务器时，用该服务器完成一次端到端注册、心跳、资源上报和任务接收验收。

## 12. 上线与回滚

本功能不需要数据库迁移。上线只重建并替换 API 与 Web；Scheduler、Ops、PostgreSQL、MinIO 和现有 Agent 不因本功能主动重启。

上线前保留当前 API/Web 镜像标识和部署文件恢复点。若发布接口或向导异常：

- 先回滚 Web，使接入入口恢复到上一个稳定版本。
- 再回滚 API 镜像，移除公开发布端点和内置安装包。
- 现有服务器身份、令牌表、任务调度和已接入代理不需要回滚数据。
- 已创建但未使用的令牌按原有 10 分钟到期机制自动失效。

不可变安装包即使被中间缓存保留也不构成权限风险；回滚后的向导不再引用该地址，且安装包本身不包含凭据。

## 13. 后续阶段与非目标

以下能力明确留到后续独立设计：

- 已接入代理的版本盘点、灰度升级、自动升级和回滚。
- 安装包代码签名、软件供应链证明或外部制品仓库。
- Windows、macOS、非 systemd Linux 和 32 位架构支持。
- 由安装程序自动修改防火墙、SSH、系统软件源或安装 OS 依赖。
- 在接入向导中远程保存 SSH 用户名、密码或私钥。
- 多控制平面镜像源、离线安装包和企业内网镜像。

## 14. 完成标准

本阶段只有同时满足以下条件才算完成：

- API 对外提供经过启动校验的 `linux/amd64` 与 `linux/arm64` 不可变安装包和完整发布清单。
- 控制台能生成一条不含令牌的完整安装命令，并彻底移除手动上传步骤。
- 两种架构都经过解包、ELF 架构、SHA-256、文件集合和 Shell 失败语义验证。
- 任一清单、下载、校验、依赖或权限错误都安全停止并给出中文提示，未经验证的内容不会以 root 执行。
- 注册令牌不出现在命令、URL、参数、进程列表、下载日志或普通应用日志中。
- 现有 Web 与 Go 测试、新增发布与向导测试、生产构建和健康检查全部通过。
- 生产公网下载与哈希验证通过，现有京东云代理和任务调度不受影响。
- 部署文档记录代理版本、两个安装包 SHA-256、生产镜像和回滚方法，且不包含任何秘密。
