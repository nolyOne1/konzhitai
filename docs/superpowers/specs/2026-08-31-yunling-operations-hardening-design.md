# 云令生产运维与安全加固设计

日期：2026-08-31  
状态：已确认，待编写实施计划

## 1. 目标

在不影响现有脚本调度、执行代理和排队规则的前提下，为云令增加可持续运行所需的运维闭环：

- 通过飞书群机器人接收关键故障和恢复通知。
- 每 6 小时自动备份 PostgreSQL、脚本包、日志和运行产物。
- 本机保留 7 天加密快照，腾讯云 COS 保留 30 天加密快照。
- 每月从 COS 执行一次自动恢复校验。
- 为管理员提供安全的自助改密入口，并撤销其他会话。
- 在中文控制台统一查看运维状态、备份历史、恢复校验和通知配置。

本阶段不引入 DAG、审批流、多地域控制中心或 Kubernetes 调度，也不改变任务无可用服务器时继续排队的现有规则。

## 2. 已确认的产品决策

- 采用云令内置运维中心，不把主要状态散落到宿主机脚本或腾讯云控制台。
- 飞书使用带签名密钥的群机器人 Webhook。
- 飞书 Webhook 和签名密钥从云令控制台录入；密钥加密保存，界面只显示脱敏信息。
- 备份每 6 小时执行一次，本机保留 7 天，COS 保留 30 天。
- 每月自动执行一次恢复校验。
- 管理员改密后立即撤销该账号的其他所有会话，保留当前会话。
- 新密码验证和重新登录成功后，删除腾讯云上的 `/root/yunling-initial-admin.txt`。
- 控制台不提供直接覆盖生产数据库的一键恢复操作。

## 3. 总体架构

### 3.1 新增 Ops 服务

新增 `cmd/ops` 长期运行服务，与 API、Scheduler 和 Agent 分离。Ops 负责：

- 扫描并执行到期备份。
- 将本机快照上传到 COS，并应用保留策略。
- 执行每月恢复校验。
- 计算服务器、队列和资源阈值告警。
- 可靠领取通知发件箱消息并发送到飞书。
- 恢复启动时接管超时租约，避免重复备份或重复通知。

Ops 不负责业务任务调度，也不直接修改运行实例状态。Ops 容器不挂载 Docker Socket、不以 root 运行，只获得 PostgreSQL、MinIO、COS 和专用备份目录所需的权限。

### 3.2 API 服务职责

API 新增以下能力：

- 读取和更新飞书机器人设置。
- 发送飞书测试消息。
- 查看备份、COS 上传和恢复校验历史。
- 请求立即备份或立即恢复校验。
- 管理员修改自己的密码。

API 继续复用现有会话、权限、秘密加密和只追加审计能力。它不执行耗时备份，也不接触 COS 或 Restic 的明文密钥。

### 3.3 Web 控制台

新增“运维中心”一级页面，保持现有中文控制台视觉和交互模式，包含：

1. **运行保障**：下一次备份时间、最近本机快照、最近 COS 快照、最近恢复校验和当前运维告警。
2. **备份历史**：备份范围、阶段状态、大小、校验值、耗时和失败原因；管理员可请求立即备份或立即校验。
3. **通知设置**：飞书 Webhook、签名密钥、启停开关、脱敏状态和发送测试消息。
4. **账号安全**：当前密码、新密码、确认密码和改密后的会话处理说明。

页面只发出命令并展示持久化状态，不依赖长连接中的瞬时结果判定成功。

## 4. 数据模型

通过新的向上/向下迁移扩展以下实体。

### 4.1 通知配置 `notification_configs`

- `channel`：首期固定为 `feishu`，保留其他渠道扩展边界。
- `enabled`：是否启用外部通知。
- `webhook_secret_id`：引用现有 `secrets` 表中加密保存的 Webhook。
- `signing_secret_id`：引用现有 `secrets` 表中加密保存的签名密钥。
- `masked_destination`：仅用于界面展示，不含可还原信息。
- `created_by`、`updated_by`、`created_at`、`updated_at`。

通知功能复用现有秘密服务和密钥版本机制，不建立第二套加密实现。数据库不保存 Webhook 或签名密钥明文，API 响应永不返回密文字段或秘密引用的可解密内容。

### 4.2 通知发件箱 `notification_outbox`

- 关联告警或测试请求。
- 事件类型：`opened`、`recovered`、`test`。
- 保存发送时已经冻结的中文消息载荷，保证重试内容一致。
- 状态：`pending`、`sending`、`retrying`、`sent`、`failed`；`failed` 只表示不可重试或达到运维上限的终态。
- 记录尝试次数、下次尝试时间、租约截止时间、最后错误和发送完成时间。
- 使用幂等键防止同一个告警状态转换产生多条相同消息。

Ops 通过 `FOR UPDATE SKIP LOCKED` 原子领取到期消息；租约过期后其他实例可以安全接管。

### 4.3 备份运行 `backup_runs`

- 触发来源：`scheduled` 或 `manual`。
- 状态：`queued`、`exporting`、`snapshotting`、`uploading`、`succeeded`、`degraded`、`failed`。
- 分别记录本机快照 ID、COS 快照 ID、备份清单 SHA-256、字节数和对象数量。
- 记录开始、完成、租约、错误摘要以及操作者。
- 同一时刻只允许一条未结束备份持有活动租约。

`degraded` 表示本机加密快照成功但 COS 上传失败。Ops 会从已有本机快照继续上传，不重新导出数据。

### 4.4 恢复校验 `restore_verifications`

- 关联被校验的 COS 快照。
- 触发来源：`scheduled` 或 `manual`。
- 状态：`queued`、`restoring`、`checking`、`succeeded`、`failed`。
- 记录数据库迁移版本、关键表计数、对象校验数量、开始/结束时间和错误摘要。
- 每条记录使用唯一临时数据库名；无论成功或失败都进入清理流程。

### 4.5 告警生命周期

复用现有 `alerts` 表的 `open`、`acknowledged` 和 `resolved` 状态，补充“按规则代码和资源定位当前未恢复告警”的仓储方法。人工确认不会等同于故障恢复；规则恢复后仍将告警置为 `resolved` 并产生恢复通知。

## 5. 备份设计

### 5.1 备份内容

每个快照包含：

- PostgreSQL 自定义格式全量导出。
- MinIO 中的脚本版本、归档日志和运行产物。
- 数据库迁移版本、服务镜像清单和非敏感部署元数据。
- 每个导出文件和对象的路径、大小、SHA-256 与生成时间。

生产 `.env`、COS SecretKey、Restic 密码和应用主密钥不写入普通清单。灾难恢复所需密钥由部署流程生成恢复密钥包，密钥只显示一次并由管理员保存到受控密码管理器。

### 5.2 工具与执行顺序

Ops 镜像固定版本安装 PostgreSQL 客户端、MinIO Client 和 Restic：

1. 获取数据库租约并检查专用备份目录剩余空间。
2. 执行 `pg_dump --format=custom`。
3. 通过 MinIO S3 API 增量镜像对象到临时导出区。
4. 生成并校验清单。
5. 使用 Restic 创建加密、去重的本机快照。
6. 将同一导出树写入 COS Restic 仓库。
7. 再次读取快照元数据确认远端可见。
8. 只有新快照成功且完整时才执行保留清理。

备份临时目录和 Restic 缓存使用独立受限目录。所有外部命令都设置最大运行时间、最大错误输出和明确退出码映射，日志不打印环境变量或命令行密钥。

### 5.3 调度和保留

- 默认每 6 小时触发一次，按 Asia/Shanghai 时区在 `00:30`、`06:30`、`12:30`、`18:30` 执行，避开整点业务任务。
- 本机保留最近 7 天快照；COS 保留最近 30 天快照。
- 清理前必须至少存在一份通过校验的新快照。
- COS 上传失败时保留本机快照并进入持久化重试。
- 多个 Ops 实例或重启恢复时由数据库租约保证同一备份只执行一次。

### 5.4 恢复校验

每月 1 日 `03:30` 自动校验最新 COS 快照：

1. 运行 Restic 仓库一致性检查。
2. 从 COS 恢复到全新临时目录。
3. 校验完整清单和所有文件 SHA-256。
4. 在 PostgreSQL 中创建随机命名的临时数据库并执行 `pg_restore`。
5. 校验迁移版本、关键表可读性、主外键关系和清单中的对象引用。
6. 删除临时数据库与目录，并记录清理结果。

校验过程设置资源和时间上限。校验失败不会修改或覆盖生产数据库。

## 6. 飞书通知设计

### 6.1 Webhook 安全

- 只接受 HTTPS。
- 主机必须是飞书官方开放平台域名。
- 路径必须匹配群机器人 Webhook 固定前缀和令牌格式。
- 禁止重定向到其他域名、私网地址、环回地址或非 HTTPS 地址。
- 使用飞书时间戳与签名密钥生成请求签名。
- HTTP 客户端设置连接、响应和总请求超时，并限制响应体大小。
- 请求和响应日志统一脱敏，不记录完整 URL、令牌、签名或密钥。

### 6.2 消息内容

通知使用简洁中文卡片，包含环境、严重级别、事件、资源名称、发生时间、合并次数和云令详情链接。首期发送：

- 服务器离线与恢复。
- 任务失败或超时。
- 任务排队超过 10 分钟及恢复分配。
- 磁盘、内存资源不足及恢复。
- 备份失败、降级、恢复上传成功。
- 恢复校验失败或成功。
- 飞书测试消息。

消息不包含脚本敏感参数、日志正文、数据库错误详情或任何凭据。

### 6.3 合并与重试

- 同类告警 5 分钟内合并计数。
- 通知失败按 1 分钟、5 分钟、15 分钟、1 小时、6 小时退避。
- 成功发送后记录飞书响应标识和时间，不保存响应中的潜在敏感内容。
- 飞书发送失败只产生控制台内部通知故障，不再向同一飞书渠道递归发送。
- “发送测试消息”通过相同发件箱和发送器执行，控制台轮询最终结果。

## 7. 告警规则

### 7.1 服务器离线

已启用服务器最后心跳超过 2 分钟时告警；恢复心跳后立即解决告警并发送恢复通知。已停用服务器不产生离线告警；主动排空的服务器仍受心跳监控，因为排空只阻止新任务分配。

### 7.2 任务状态

- 任务进入 `failed` 或 `timed_out` 时立即告警。
- 运行保持 `queued` 超过 10 分钟时告警。
- 超时排队任务成功分配、被取消或结束后解决对应告警。
- 同一运行实例只产生一个当前状态告警，重试运行使用新的运行 ID。

### 7.3 服务器资源

- 磁盘剩余低于 15% 时告警，高于 20% 并连续满足两个心跳周期后恢复。
- 内存可用低于 10% 时告警，高于 15% 并连续满足两个心跳周期后恢复。
- 开启告警前也要求连续两个有效心跳样本，忽略缺失、过期或无效指标。

### 7.4 运维任务

备份失败、COS 降级和恢复校验失败立即告警。后续上传或校验成功时解决对应告警并发送恢复消息。

所有规则均从 PostgreSQL 最终状态计算，Ops 重启后重新扫描不会重复创建相同未恢复告警。

## 8. 管理员改密

新增 `POST /api/auth/password`：

- 请求包含当前密码、新密码和当前会话身份，不接受目标用户 ID。
- 仅允许已登录用户修改自己的密码。
- 当前密码必须重新验证。
- 新密码至少 12 位，不能与当前密码相同，并使用现有 Argon2id 参数生成新哈希。
- 密码更新、其他会话撤销和审计记录在同一数据库事务中完成。
- 当前会话保留，其他未过期会话立即设置 `revoked_at`。
- 成功响应使用 `Cache-Control: no-store`；请求体和验证错误不进入日志。
- 接口按账号和来源地址限速，失败响应不区分账号、当前密码或策略细节。

生产上线时先使用新密码重新登录并确认会话有效，再由部署操作删除 `/root/yunling-initial-admin.txt`。删除行为和文件不存在的检查写入生产验收记录，但不把密码内容写入记录。

## 9. API 与权限

首期新增接口：

- `GET /api/operations/summary`
- `GET /api/operations/backups`
- `POST /api/operations/backups`
- `GET /api/operations/verifications`
- `POST /api/operations/verifications`
- `GET /api/operations/notifications/feishu`
- `PUT /api/operations/notifications/feishu`
- `POST /api/operations/notifications/feishu/test`
- `GET /api/operations/notifications/{id}`
- `POST /api/auth/password`

读取运维状态需要只读权限；请求备份、恢复校验、修改通知配置和发送测试消息需要管理员权限；修改本人密码需要有效会话。所有写操作使用 SameSite 会话 Cookie、显式 Origin 校验、内容类型校验和现有审计记录机制。

手动操作使用幂等键防止浏览器重试产生重复备份或重复测试通知。

## 10. COS 与密钥管理

- 使用现有腾讯云 COS 存储桶的 S3 兼容接口。
- 创建只允许指定备份前缀列出、读取、写入和删除的最小权限凭据。
- COS 凭据、Restic 密码和仓库地址放入腾讯云 root-only 运维配置，并只读挂载给 Ops。
- Restic 密码不进入数据库，因此数据库泄露不足以解密备份。
- 恢复密钥包由管理员保存到服务器之外的密码管理器；上线前必须完成一次脱离生产环境配置的读取验证。
- COS 存储桶启用服务端加密和版本控制；Restic 同时提供客户端加密。
- 飞书密钥单独使用应用主密钥加密，不能与备份密钥复用。

## 11. 异常处理

- **空间不足**：估算空间不足或低于安全水位时不开始导出，记录失败并告警。
- **PostgreSQL 导出失败**：清理未完成导出，不创建可见快照。
- **MinIO 镜像失败**：保留诊断元数据，清理不完整导出，不上传 COS。
- **本机快照成功、COS 失败**：状态记为 `degraded`，保留本机快照并持续重试上传。
- **保留清理失败**：不影响已完成快照，单独告警并在下一周期重试。
- **恢复校验失败**：保留有界诊断信息，优先清理临时数据库和目录；清理失败升级为严重告警。
- **Ops 中途退出**：租约到期后接管；已完成的外部步骤通过快照 ID 和幂等键识别，不重复覆盖。
- **飞书不可用**：业务服务继续运行，发件箱持久化等待重试。
- **通知配置错误**：测试消息返回持久化失败状态；原有有效配置只有在新配置验证和加密成功后才被替换。

所有错误信息限制长度并脱敏，详细命令输出只保留允许的诊断字段。

## 12. 可观测性与审计

Ops 提供独立健康检查，至少包含数据库连接、租约扫描时间、待发送通知数量、最近备份和最近恢复校验时间。生产容器健康检查只判断服务能否继续工作，不因单次 COS 或飞书故障反复重启服务。

新增审计动作：

- `operations.backup.request`
- `operations.verification.request`
- `operations.feishu.update`
- `operations.feishu.disable`
- `operations.feishu.test`
- `auth.password.change`

审计详情只记录资源标识、脱敏目标和结果，不记录密码、Webhook、签名、COS 凭据、Restic 密码或完整外部错误响应。

## 13. 测试策略

### 13.1 单元测试

- 飞书签名、域名与路径校验、重定向拒绝、响应体限制和日志脱敏。
- 发件箱原子领取、幂等、租约恢复和五档退避。
- 告警开启、合并、确认、恢复和阈值回差。
- 备份状态机、空间检查、保留前置条件和降级上传恢复。
- 当前密码校验、密码策略、哈希更新和其他会话撤销。

### 13.2 集成测试

- PostgreSQL 迁移向上和向下执行。
- 并发 Ops 实例只能领取一次备份和一次通知。
- 使用临时 MinIO 和 S3 兼容目标完成导出、Restic 快照、恢复和 SHA-256 校验。
- 将数据库快照恢复到随机临时数据库并验证迁移版本和关键关系。
- 模拟 COS、飞书和 PostgreSQL 暂时不可用后恢复。

### 13.3 Web 与端到端测试

- 运维中心加载、空状态、权限控制和移动端布局。
- 飞书设置保存后脱敏，刷新页面不泄露明文。
- 测试通知从排队到成功或失败的状态变化。
- 立即备份和立即校验的防重复提交。
- 改密表单、错误焦点、当前会话保留和其他会话失效。

### 13.4 生产验收

按以下顺序执行一次：

1. 部署加法型数据库迁移和 Ops 服务，确认现有七个服务及任务调度不受影响。
2. 配置最小权限 COS 凭据、Restic 密钥和飞书机器人。
3. 发送一条带“云令生产测试”标识的飞书测试消息。
4. 生成一份真实备份，确认本机和 COS 快照、清单与校验值一致。
5. 从该 COS 快照执行一次真实恢复校验，确认生产数据未被修改。
6. 管理员在控制台修改密码，验证新密码重新登录和旧密码失效。
7. 删除 `/root/yunling-initial-admin.txt` 并确认文件不存在。
8. 验证所有服务健康、京东云代理在线、没有新增业务任务或残留校验资源。

## 14. 上线与回滚

上线采用加法型迁移：先部署数据库表和兼容 API，再启动 Ops，最后开放 Web 导航。未配置飞书或 COS 时 Ops 保持明确的“未配置”状态，不影响原有系统。

回滚时先停止 Ops，再回滚 Web/API；新增表在确认不再需要历史记录前不立即删除。任何生产变更前先保留 PostgreSQL、现有对象存储和部署配置的 root-only 恢复点并记录 SHA-256。

## 15. 完成标准

本阶段只有同时满足以下条件才算完成：

- 飞书测试、故障告警和恢复通知均可达，且没有密钥泄露。
- 连续两次定时备份按计划完成，COS 与本机保留策略正确。
- 至少一次 COS 恢复校验成功，临时资源全部清理。
- 管理员改密、其他会话撤销和重新登录通过。
- 初始管理员凭据文件已安全删除。
- 全量 Go、集成、Web、端到端和生产健康验证通过。
- 部署与恢复文档更新，生产验收证据不包含任何凭据或敏感日志。
