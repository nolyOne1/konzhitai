# 平台功能补齐

本次以既有中文调度平台设计和已接受的派发、升级、运维方案为范围。执行顺序为先完成业务链路，再进行统一回归。本文记录代码能力，不代表生产已经部署。

## 功能入口

| 模块 | 补齐的操作与结果 |
| --- | --- |
| 运行总览 | 每 5 秒刷新真实活动任务、节点和当前发布版本同步统计；刷新失败保留上次成功数据并标明状态。 |
| 服务器组 | 创建、改名、调整节点归属；脚本发布使用实际分组选择器；历史组标识自动回填。 |
| 脚本同步 | 失败后自动退避重试，连续失败达到 3 次后可手动重置；失败与漂移版本不可调度；单个脚本失败不隔离整台服务器。 |
| 脚本参数 | 可维护参数类型、必填与说明；运行创建时按已经解析的不可变脚本版本校验任务默认值与本次覆盖值。 |
| 任务与计划 | 修改现有 Cron、增删多个计划、保留计划启停；0 秒等待表示不限时。 |
| 手动执行 | 确认窗口允许修改本次普通参数；历史终态可按当前任务配置创建独立的新运行。原有安全重试继续遵守幂等、次数和进程确认条件。 |
| 执行记录 | 服务端关键词、状态、任务、脚本、服务器、时间筛选和分页，能访问较早的记录。 |
| 日志 | 下载全部已持久化日志；终态大日志自动归档至对象存储；迟到日志触发重新归档，旧快照不冒充完整日志。 |
| 资源用量 | 支持 systemd 的节点采集累计 CPU 时间、内存、观测内存峰值与进程数；显示采样时间，不支持的数值显示缺失。 |
| 运行产物 | 脚本可启用顶层文件白名单与大小限制，执行结束后上传；详情页列出大小、摘要并提供受保护下载。 |
| 权限与审计 | 任务及运行写操作按管理员、运维角色显示；执行详情可跳转本次运行和关联任务审计。 |
| 运维与发布 | 备份记录显示摘要、时长与失败原因；测试通知请求幂等；备份读取真实迁移版本；新增受控 15→19 迁移路径。 |

## 使用约定

- 普通参数采用 JSON 类型；数字 `0`、布尔 `false` 均是有效值。敏感参数继续使用密钥引用，不在创建运行时解密。
- 新运行保存创建时的密钥引用，后续任务配置编辑不会改变已排队运行的引用；安全重试沿用该快照。密钥值继续在派发阶段读取。
- “按当前任务配置再次执行”使用当前参数和版本策略，可能与历史运行不同；“安全重试”沿用原运行快照和原有防重复规则。
- 日志默认达到 1 MiB、运行已经结束且接收静置至少 30 秒后进入归档候选；后台每分钟扫描。数据库日志保留供实时读取及普通下载。
- 资源每 5 秒采样，随代理报告送达。很短的任务或不支持计量的旧节点可能没有样本；观测峰值不等同于高频性能剖析。资源属性遵循 [systemd 官方接口说明](https://github.com/systemd/systemd/blob/main/man/org.freedesktop.systemd1.xml)。
- 产物采集默认关闭；只处理本次工作目录顶层普通文件。最大单文件 100 MiB、总量 500 MiB、100 个文件，仍须符合脚本配置的更低上限。隐藏文件、链接和代理保留文件不采集。
- 启用产物策略后，需要上报 `run_artifacts_v1` 能力的代理。未具备能力的节点不会接收该脚本的新运行。
- 代理 0.2.6 发布清单显式声明自升级和运行产物能力；导入时校验原始清单摘要、能力及双架构文件信息。旧清单仍兼容，版本号不会自动赋予新能力。
- 产物上传发生在终态上报之后；详情页会刷新列表。上传失败保留脚本真实退出状态，并在系统日志中说明。

## 交付与检查

数据库新增迁移 16–19；升级需使用受控恢复点和候选绑定，具体步骤见 [发布手册](../deploy/RELEASE.md)。应用与代理分别生成候选并验证；本次代码变更本身不执行生产迁移、任务运行或通知发送。

综合检查涵盖 Go 测试与竞态检查、Web 组件与生产构建、浏览器流程、Linux systemd、代理打包与部署配置。实际执行结果以本次提交对应的测试日志和 CI 为准。DAG、多地域容灾与多租户计费继续不在既有一期范围。
